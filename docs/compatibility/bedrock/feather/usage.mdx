# 🕹️ Usage

## Overview
FeatherConvert reads the resource pack generated by Oraxen and creates the Bedrock files needed by Geyser. Oraxen's pack must be readable during conversion, so disable pack protection and obfuscation first.

## Conversion

<Callout type="important">
  Both `obfuscation.type: NONE` and `protection: false` are required. Oraxen pack protection and obfuscation prevent FeatherConvert from reading the generated files.
</Callout>

<Steps>
### Disable protection and obfuscation

Open `plugins/Oraxen/settings.yml` and make sure the pack generation settings contain.

```yaml
Pack:
  generation:
    obfuscation:
      type: NONE
    protection: false
```

### Match the mapping mode

FeatherConvert can read either of Oraxen's appearance formats. `mapping_mode: auto` is recommended because it detects the format from the generated pack.

- `Pack.generation.appearance.item_properties: true` uses the `definitions` format and modern `item_model` files such as `assets/oraxen/items/<id>.json`.
- `Pack.generation.appearance.model_data_float: true` uses the `legacy` format and numeric custom-model-data values.

### Regenerate the pack

```text
/oraxen reload pack
```

### Convert the pack

```text
/feather convert oraxen
```

FeatherConvert finds the generated pack in `plugins/Oraxen/pack/pack.zip` and reads Oraxen item configuration from `plugins/Oraxen/items/`.
</Steps>

<Callout type="info">
  Furniture is read from Oraxen's `display_entity_properties`. Growth-stage files are assigned to the item that owns them during conversion.
</Callout>

<Details>
<summary id="gui-commands"><strong>🖼️ Chest GUIs</strong></summary>

Starts live measurement while you open chest menus.

```yml
/feather gui import live
```

Stops an active live measurement session.

```yml
/feather gui import live stop
```

Imports a glyph or a PNG from `plugins/FeatherConvert/gui/` with a specified row count.

```yml
/feather gui import &lt;name&gt; [row]
```

Lists the chest GUI measurements saved by FeatherConvert.

```yml
/feather gui list
```

Removes a saved chest GUI measurement.

```yml
/feather gui remove &lt;id&gt;
```

Live measurement stops automatically after five minutes.
</Details>

## GeyserUtils on proxy networks

If your integration exchanges live server data with Geyser, install `geyserutils-geyser` in Geyser's `extensions/` directory and exactly one platform bridge in the matching `plugins/` directory:

- [GeyserUtils Geyser extension](https://github.com/GeyserExtensionists/GeyserUtils/releases/download/latest/geyserutils-geyser-1.0-SNAPSHOT.jar)
- [GeyserUtils Spigot bridge](https://github.com/GeyserExtensionists/GeyserUtils/releases/download/latest/geyserutils-spigot-1.0-SNAPSHOT.jar)
- [GeyserUtils Velocity bridge](https://github.com/GeyserExtensionists/GeyserUtils/releases/download/latest/geyserutils-velocity-1.0-SNAPSHOT.jar)
- [GeyserUtils BungeeCord bridge](https://github.com/GeyserExtensionists/GeyserUtils/releases/download/latest/geyserutils-bungee-1.0-SNAPSHOT.jar)

<Callout type="warning">
  If you previously used another converter, remove its old mapping files before installing FeatherConvert. Multiple mapping files for the same furniture can produce undefined results.
</Callout>

For a proxy setup, install Floodgate on the proxy and every backend server. Copy the proxy's `key.pem` to each backend Floodgate folder, then enable `send-floodgate-data: true` in the proxy Floodgate configuration.

## Chest GUIs

FeatherConvert can measure custom chest GUI backgrounds and include them in the next conversion. Live import is recommended because it reads the actual glyph and row count from the menu.

The available GUI commands are listed in the <Highlight color="#1877F2" to="#gui-commands">**command reference**</Highlight>. Live measurement stops automatically after five minutes. Manual imports can use a glyph or a PNG from `plugins/FeatherConvert/gui/`.

Measurements are saved in `plugins/FeatherConvert/gui.yml`. They are not applied until the next `/feather convert`.

```yaml
guis:
  menu_items:
    row: 6
    offsetX: 49.9
    offsetY: 88
    unicode: "U+A457"
    container: chest_6
```

## Emotes and glyphs

Glyphs convert automatically at their authored size. Use `plugins/FeatherConvert/glyphs.yml` when you need to change their **Bedrock size**.

- `scale` multiplies the authored size while preserving the relative size between glyphs.
- `height` sets an exact pixel height and takes priority over `scale`.
- `supersample: true` uses the full-resolution image when a larger source is available.

The resolved glyph height is limited to 256 pixels. Bedrock resamples the image, so increasing a glyph's size does not add detail.

<Details>
  <summary><strong>🔤 Glyph configuration</strong></summary>

```yaml
# plugins/FeatherConvert/glyphs.yml
glyphs:
  farmer_tag:
    scale: 2.0
  god_tag:
    height: 36
  some_big_logo:
    supersample: true

fonts: {}
```

`glyphs` accepts glyph IDs, which are the keys in an Oraxen glyph file. It does not accept the glyph file name or texture path. `fonts` accepts font names and applies a setting to every glyph in that font.
</Details>

## Items without a material

Some models do not specify which vanilla material they represent. FeatherConvert asks for those materials during conversion and saves the answers in `plugins/FeatherConvert/pending/pending_materials.json`.

Use either `paper` or `minecraft:paper`. Leaving an entry empty converts the pack without a Bedrock mapping for that item. Set `skip_pending: true` to skip the prompt; saved answers still apply.

## Settings

FeatherConvert presents these options before conversion and saves the selected values as defaults. Each setting is shown below in the same format as Oraxen's `settings.yml` documentation.

<Details>
<summary id="mapping-mode"><strong>🗺️ `mapping_mode`</strong></summary>

Selects how Geyser mapping rows are generated.

```yaml
mapping_mode: auto
```

`mapping_mode` - Uses `auto` to detect the pack format, `legacy` for custom-model-data rows, or `definitions` for 1.21.4 item-model rows.<br />

</Details>

<Details>
<summary id="icon-size"><strong>🖼️ `icon_size`</strong></summary>

Controls the resolution of rendered inventory icons.

```yaml
icon_size: 64
```

`icon_size` - Sets the icon resolution. Valid values are `16`, `32`, `64`, and `128`. Other values use the nearest supported size.<br />

</Details>

<Details>
<summary id="transparency"><strong>🔳 `transparency`</strong></summary>

Controls how semi-transparent textures are detected during conversion.

```yaml
transparency: true
```

`transparency` - Detects semi-transparent pixels so textures render correctly instead of as solid blocks.<br />

</Details>

<Details>
<summary id="font"><strong>🔤 `font`</strong></summary>

Controls conversion of Java bitmap fonts into Bedrock glyph pages.

```yaml
font: true
```

`font` - Converts custom fonts so glyphs can appear in Bedrock chat, names, and menus.<br />

</Details>

<Details>
<summary id="skip-pending"><strong>❓ `skip_pending`</strong></summary>

Controls what happens when an item has no vanilla material mapping.

```yaml
skip_pending: false
```

`skip_pending` - Skips the material prompt when enabled. Saved answers still apply, while items without an answer are left without a Bedrock mapping.<br />

</Details>

<Callout type="info">
  The texture atlas is always enabled. Disabling it would make larger packs download as thousands of separate files.
</Callout>

## Supported features

- 🟢 × **Items, 2D and 3D.** 3D models become held Bedrock models and flat items become sprites.
- 🟢 × **Bows, crossbows, and tridents.** Draw, charge, and throw poses are rebuilt for Bedrock.
- 🟢 × **Custom blocks.** Note-block, string, chorus, stairs, slabs, doors, trapdoors, and cross-shaped plants retain their supported shapes and sounds.
- 🟢 × **Block hitboxes.** Custom block collision sizes are converted.
- 🟢 × **Player armor.** Custom equipment textures render as worn armor.
- 🟢 × **Glyphs and emotes.** Java bitmap fonts become Bedrock glyph sheets.
- 🟢 × **Custom sounds.** Sound events are remapped for Bedrock.
- 🟢 × **Item components.** Food, consumables, tools, repairable items, and use cooldowns are carried over.
- 🟢 × **Animated textures.** Animation strips are rebuilt as Bedrock frame animations.
- 🟠 × **Furniture.** Requires [GeyserDisplayEntity](https://github.com/GeyserExtensionists/GeyserDisplayEntity/releases/latest). Position, scale, and offset use the model's display settings.
- 🟠 × **ModelEngine.** Requires [GeyserModelEngine](https://github.com/GeyserExtensionists/GeyserModelEngine/releases/latest) to render converted bundles.

## Limitations

- 🟠 × **Dyeable models and furniture.** Bedrock cannot read the item color for these models.
- 🟠 × **Custom elytras.** Wings render as worn armor, but Bedrock players cannot glide with them.
- 🟠 × **ModelEngine rotations.** Some models can have an incorrect rotation in specific cases.
- 🔴 × **Armor worn by mobs.** Custom horse and wolf armor does not render on Bedrock.
- 🔴 × **Custom paintings.** Bedrock players see the vanilla paintings.
- 🔴 × **Hopper, dropper, and dispenser reskins.** These screens are built into the Bedrock client and cannot be changed by a resource pack.
- 🟠 × **MythicHUD and BetterHUD.** These plugins render HUDs from their own configuration rather than pack assets, so they require a Bedrock JSON UI integration.

<Callout type="note">
  Most limitations come from Bedrock or Geyser rather than Oraxen or FeatherConvert. Report one specific item, block, or furniture problem with a screenshot in the [FeatherConvert Discord](https://discord.gg/4f3V6X2deY).
</Callout>

# 📖 Recipes

## Overview
Oraxen supports multiple custom recipe types and loads them from `.yml` files in the `plugins/Oraxen/recipes` folder. You can create recipes through the ingame builder, edit them manually, reload them without restarting the server, and disable vanilla or existing recipes by namespaced key.

### Supported Recipe Types
`shaped.yml` - Standard crafting recipes where ingredient position matters.<br />
`shapeless.yml` - Crafting recipes where ingredient order does not matter.<br />
`furnace.yml` - Furnace smelting recipes with time and experience.<br />
`blasting.yml` - Blast furnace recipes with time and experience.<br />
`campfire.yml` - Campfire cooking recipes with time and experience.<br />
`smoking.yml` - Smoker recipes with time and experience.<br />
`stonecutting.yml` - Stonecutter recipes with one input and one result.<br />
`smithing.yml` - Smithing table transform recipes with template, base, and addition inputs.<br />
`cauldron.yml` - Recipes performed by right-clicking a cauldron with an input item.<br />
`anvil.yml` - Fixed-output anvil recipes with an optional addition and level cost.<br />
`grindstone.yml` - Fixed-output grindstone recipes with an optional addition and experience reward.<br />
`disabled.yml` - Recipe keys that should be removed when Oraxen loads recipes.<br />

### Item Definitions
Recipe inputs and results support several item formats.

`oraxen_item` - Use an Oraxen item ID.<br />
`minecraft_type` - Use a vanilla material such as `DIAMOND` or `STICK`.<br />
`minecraft_item` - Use a fully serialized Bukkit `ItemStack`.<br />
`tag` - Use a vanilla item or block tag as an ingredient, such as `planks` or `minecraft:logs`. <Highlight color="#2E8B57">**Ingredients only**</Highlight><br />
`crucible_item` - Use a MythicCrucible item ID. <Highlight color="#2E8B57">**Optional compatibility**</Highlight><br />
`mmoitems_type` + `mmoitems_id` - Use an MMOItems item. <Highlight color="#2E8B57">**Optional compatibility**</Highlight><br />
`ecoitem_id` - Use an EcoItems item ID. <Highlight color="#2E8B57">**Optional compatibility**</Highlight><br />
`amount` - Set a result stack size, a shapeless ingredient count, or the amount consumed by a cauldron, anvil, or grindstone recipe.<br />
`permission` - Require a permission to use a shaped, shapeless, smithing, cauldron, anvil, or grindstone recipe. <Highlight color="#2E8B57">**Optional**</Highlight><br />

<Callout type="info">
  Oraxen creates the recipe files automatically on first load, except `disabled.yml`. You can add entries manually or generate them ingame with the recipe builder.
</Callout>

<Callout type="note">
  Existing installations may need to create the new `smithing.yml`, `cauldron.yml`, `anvil.yml`, and `grindstone.yml` files manually before adding recipes. `disabled.yml` must also be created manually in `plugins/Oraxen/recipes/`; it is only auto-created when `Plugin.generation.default_configs` is `false`.
</Callout>

## Recipe Groups
Recipes can optionally define a `group` to combine alternative recipes into one Minecraft recipe book entry. Recipes are grouped when they produce the same result and use the same non-empty `group` value.

`group` is supported by shaped, shapeless, furnace, blasting, smoking, campfire, and stonecutting recipes. Smithing, cauldron, anvil, and grindstone recipes do not support recipe groups.

```yaml
obsidian_ingot_from_obsidian:
  group: obsidian_ingot
  result:
    oraxen_item: obsidian_ingot
  ingredients:
    A:
      minecraft_type: OBSIDIAN
      amount: 1

obsidian_ingot_from_crying_obsidian:
  group: obsidian_ingot
  result:
    oraxen_item: obsidian_ingot
  ingredients:
    A:
      minecraft_type: CRYING_OBSIDIAN
      amount: 1
```

<Callout type="note">
  Omitting `group` or leaving it empty keeps the recipes as separate recipe book entries.
</Callout>

## Recipe Formats

<details>
<summary id="shaped"><strong>🧩 Shaped</strong></summary>

Use `shape` and `ingredients` together. Each character in `shape` maps to one entry in `ingredients`, while `_` means an empty slot.

`shape` - Up to three crafting rows.<br />
`ingredients` - Character-to-item mapping.<br />
`result` - Crafted output item.<br />

```yaml
bedrock_pickaxe:
  shape:
    - AAA
    - BCB
    - _D_
  result:
    oraxen_item: bedrock_pickaxe
  ingredients:
    A:
      minecraft_type: DIAMOND_BLOCK
    B:
      minecraft_type: OBSIDIAN
    C:
      minecraft_type: NETHER_STAR
    D:
      minecraft_type: STICK
```
</details>

<details>
<summary id="shapeless"><strong>🌀 Shapeless</strong></summary>

Shapeless recipes ignore slot position. Each ingredient entry should include an `amount`.

`ingredients` - Arbitrary ingredient keys such as `A`, `B`, `C`.<br />
`amount` - How many times that ingredient must appear.<br />
`result` - Crafted output item.<br />

```yaml
obsidian_mix:
  result:
    oraxen_item: obsidian_ingot
  ingredients:
    A:
      minecraft_type: OBSIDIAN
      amount: 2
    B:
      tag: coals
      amount: 1
```
</details>

<details>
<summary id="cooking-recipes"><strong>🔥 Cooking Recipes</strong></summary>

`furnace.yml`, `blasting.yml`, `campfire.yml`, and `smoking.yml` all use the same structure.

`input` - The item that gets cooked.<br />
`result` - The cooked output item.<br />
`cookingTime` - Cooking duration in ticks.<br />
`experience` - Experience granted when the recipe completes.<br />

```yaml
amethyst:
  experience: 200
  cookingTime: 200
  result:
    oraxen_item: amethyst
  input:
    oraxen_item: amethyst_ore
```
</details>

<details>
<summary id="stonecutting"><strong>🪨 Stonecutting</strong></summary>

Stonecutting recipes use one `input` and one `result`.

```yaml
polished_obsidian:
  result:
    oraxen_item: polished_obsidian_tile
  input:
    minecraft_type: OBSIDIAN
```
</details>

<details>
<summary id="smithing"><strong>🔨 Smithing</strong></summary>

Smithing recipes use the smithing table's three input slots. Paper performs the native smithing transform, so data components copied from the base item are preserved.

`template` - Item in the smithing template slot.<br />
`base` - Item being transformed.<br />
`addition` - Material added to the base.<br />
`result` - Result template for the transform.<br />

```yaml
ruby_upgrade:
  permission: oraxen.recipe.ruby_upgrade
  template:
    minecraft_type: NETHERITE_UPGRADE_SMITHING_TEMPLATE
  base:
    oraxen_item: obsidian_sword
  addition:
    oraxen_item: ruby
  result:
    oraxen_item: ruby_sword
```
</details>

<details>
<summary id="anvil"><strong>⚒️ Anvil</strong></summary>

Anvil recipes produce a fixed result. The addition is optional; when omitted, the second input slot must be empty.

`base` - Required first input.<br />
`addition` - Optional second input.<br />
`result` - Fixed output item.<br />
`experience_cost` - Player levels consumed when taking the result. Defaults to `0`.<br />

Ingredient sections support `amount` to consume more than one item from that slot.

```yaml
repair_obsidian_sword:
  permission: oraxen.recipe.repair_obsidian_sword
  experience_cost: 5
  base:
    oraxen_item: damaged_obsidian_sword
  addition:
    oraxen_item: obsidian_ingot
    amount: 2
  result:
    oraxen_item: obsidian_sword
```

<Callout type="note">
  Custom anvil recipes use a fixed transaction and do not apply vanilla rename, repair, enchantment-merging, or anvil-damage behavior.
</Callout>
</details>

<details>
<summary id="grindstone"><strong>🗿 Grindstone</strong></summary>

Grindstone recipes also produce a fixed result. A recipe without `addition` accepts its base in either input slot.

`base` - Required input.<br />
`addition` - Optional second input.<br />
`result` - Fixed output item.<br />
`experience` - Experience points granted when taking the result. Defaults to `0`.<br />

```yaml
extract_ruby:
  experience: 7
  base:
    oraxen_item: ruby_sword
  result:
    oraxen_item: ruby
```

<Callout type="note">
  Custom grindstone recipes do not apply vanilla disenchanting or durability-combination behavior. Vanilla slot restrictions may still prevent some item types from being shift-clicked into the inputs; they can be placed directly when accepted by Paper.
</Callout>
</details>

<details>
<summary id="cauldron"><strong>🪣 Cauldron</strong></summary>

Cauldron recipes run when a player right-clicks the matching cauldron with the configured input in their main hand. The result is added to the player's inventory, and overflow is dropped at the cauldron.

`input` - Held item to consume.<br />
`result` - Item produced.<br />
`fluid` - `water`, `lava`, `powder_snow`, or `empty`. Defaults to `water`.<br />
`level` - Exact required water or powder-snow level from `1` to `3`. Defaults to `1`; lava and empty cauldrons use `1`.<br />
`level_change` - Level change after crafting. When omitted, filled cauldrons default to `-1` and empty cauldrons default to `0`. Empty cauldrons only accept `0`; any other value fails recipe loading.<br />

Water and powder-snow changes may reduce the level to an empty cauldron or raise it up to level `3`. Lava supports `-1` to empty the cauldron or `0` to preserve it.

```yaml
wash_ruby:
  permission: oraxen.recipe.wash_ruby
  fluid: water
  level: 2
  level_change: -1
  input:
    oraxen_item: unwashed_ruby
    amount: 2
  result:
    oraxen_item: ruby
```
</details>

## Ingame Builder

### Commands
You can create recipes ingame with the recipe builder commands listed on the [commands page](commands#recipes).

```yml
/oraxen recipes builder shaped
/oraxen recipes builder shapeless
/oraxen recipes builder furnace <cookingtime> <experience>
/oraxen recipes builder blasting <cookingtime> <experience>
/oraxen recipes builder campfire <cookingtime> <experience>
/oraxen recipes builder smoking <cookingtime> <experience>
/oraxen recipes builder stonecutting
/oraxen recipes save <name> [permission]
```

### Workflow
1. Open the builder for the recipe type you want.
2. Place the input ingredients in the builder UI.
3. Place the output item in the result slot.
4. Run `/oraxen recipes save <name>` to write the recipe to the matching `.yml` file.
5. Run `/oraxen reload recipes` or restart the server to register the new recipe.

<Callout type="note">
  Running `/oraxen recipes builder` with no type reopens your current builder if one is already active.
</Callout>

<Callout type="warning">
  Recipe builders are player-only commands. Cooking builders require both `cookingtime` and `experience` arguments when you create them.
</Callout>

<Callout type="note">
  Smithing, cauldron, anvil, and grindstone recipes currently need to be configured manually in their matching YAML files.
</Callout>

## Recipe Showcase And Permissions

`permission` can be added to shaped, shapeless, smithing, cauldron, anvil, and grindstone recipes, or passed when saving a supported builder recipe.<br />
Players without that permission cannot use the recipe.<br />

Crafting-table recipes can also appear in `/oraxen recipes show`, which opens Oraxen's showcase GUI for recipes the player is allowed to use.

<Callout type="info">
  The showcase GUI is built from Oraxen's whitelisted crafting recipes, so it applies to crafting-style recipes rather than furnace-like cooking recipes.
</Callout>

## Disabling Existing Recipes
You can disable vanilla or already-registered recipes by adding their namespaced keys to `disabled.yml`.

```yaml
disabled:
  - minecraft:diamond_sword
  - minecraft:iron_pickaxe
  - oraxen:custom_recipe
```

Oraxen attempts to remove each listed recipe whenever recipes load or reload.

<Callout type="warning">
  Invalid keys or recipes that do not exist will log a warning in the console.
</Callout>

## Notes

<Callout type="info">
  If you edit recipe files manually, use `/oraxen reload recipes` to apply the changes without a full server restart.
</Callout>

<Callout type="note">
  If `settings.yml` has recipe-book support enabled, Oraxen automatically discovers permitted recipes for players when they join.
</Callout>
